## Глава 1. Теоретический фундамент алгоритмов сортировки

### 1.1. Информационно-теоретическая нижняя граница сложности сортировок сравнением

> **Вопрос преподавателя:** *«Почему ни один алгоритм сортировки, основанный на парных сравнениях, не может работать быстрее $\Omega(n \log n)$ в худшем и среднем случаях? Можно ли отсортировать быстрее?»*

#### Строгое математическое доказательство (Модель дерева решений):
1. **Модель вычислений:** Любой алгоритм сортировки сравнениями можно представить в виде бинарного **дерева решений** (decision tree).
   - В каждой внутренней вершине дерева выполняется сравнение двух элементов $a[i] \gtrless a[j]$.
   - В зависимости от результата сравнения (True или False) алгоритм переходит в левого или правого потомка.
   - В листьях дерева располагаются окончательные перестановки элементов исходного массива.
2. **Число листьев:** Для массива из $n$ попарно различных элементов существует ровно $n!$ возможных входных перестановок. Чтобы алгоритм был корректен на любом входе, каждый возможный упорядоченный исход должен быть представлен хотя бы в одном листе. Следовательно, число листьев $L$ удовлетворяет неравенству:
   $$ L \ge n! $$
3. **Высота дерева и число сравнений:**
   - Пусть $h$ — высота дерева решений (длина самого длинного пути от корня к листу). Высота дерева соответствует *наибольшему числу сравнений в худшем случае*.
   - Бинарное дерево высоты $h$ может иметь не более $2^h$ листьев:
     $$ 2^h \ge L \ge n! \implies h \ge \log_2(n!) $$
4. **Формула Стирлинга:**
   Логарифмируя факториал через приближение Стирлинга $\ln(n!) = n \ln n - n + O(\ln n)$:
   $$ \log_2(n!) = \sum_{i=1}^n \log_2 i \ge \sum_{i=\lceil n/2 \rceil}^n \log_2 i \ge \frac{n}{2} \log_2 \left(\frac{n}{2}\right) = \frac{n}{2} (\log_2 n - 1) = \Omega(n \log n) $$
5. **Вывод:** Высота дерева $h = \Omega(n \log n)$. Следовательно, любой детерминированный или рандомизированный алгоритм сортировки, опирающийся исключительно на сравнения пар элементов, в худшем случае требует не менее $\Omega(n \log n)$ операций.

#### Можно ли быстрее?
Да, но **только выйдя за пределы модели сравнений**:
- Алгоритмы линейной сортировки (**Counting Sort, Radix Sort, Bucket Sort**) используют цифровую или адресную природу ключей (доступ по индексу массива за $O(1)$) и могут достигать времени $O(n \cdot k)$ или $O(n + M)$, где $k$ — длина ключа в разрядах, а $M$ — диапазон значений.

### 1.2. Классификация свойств алгоритмов сортировки

| Характеристика | Точное математическое определение | Практическое значение |
| :--- | :--- | :--- |
| **Стабильность (Stability)** | Если $i < j$ и $\mathrm{key}(a[i]) = \mathrm{key}(a[j])$, то после сортировки элемент $a[i]$ предшествует $a[j]$. | Критично при многокритериальной сортировке (по нескольким полям таблицы). |
| **In-place (Сортировка на месте)** | Требует $O(1)$ (в строгом смысле) или $O(\log n)$ (в ослабленном смысле для стека рекурсии) вспомогательной памяти сверх входа. | Позволяет обрабатывать большие массивы без удвоения расхода RAM. |
| **Адаптивность (Adaptivity)** | Время работы алгоритма уменьшается при уменьшении исходного числа инверсий во входном массиве ($T(n) = O(n + I)$). | Алгоритм работает в разы быстрее на частично или полностью упорядоченных данных. |

## Глава 2. Детальный разбор четырёх алгоритмов

### 2.1. Сортировка пузырьком (`bubble_sort`)

```python
def bubble_sort(a: list, key=None) -> tuple[list, int, int]:
    res = list(a)
    n = len(res)
    comparisons, swaps = 0, 0
    kfn = key if key is not None else (lambda x: x)
    for i in range(n):
        swapped = False
        for j in range(n - 1 - i):
            comparisons += 1
            if kfn(res[j]) > kfn(res[j + 1]):
                res[j], res[j + 1] = res[j + 1], res[j]
                swaps += 1
                swapped = True
        if not swapped:
            break
    return res, comparisons, swaps
```

#### Инвариант внешнего цикла:
> Перед началом $i$-й итерации подмассив `res[n - i .. n - 1]` содержит $i$ максимальных элементов массива в окончательных позициях и в отсортированном порядке.

#### Анализ сложности и счётчиков:
- **Число сравнений:**
  - *Лучший случай (упорядоченный вход):* ровно $n - 1$ сравнений. Флаг `swapped` остаётся `False`, внешний цикл немедленно прерывается. Время: $\Theta(n)$.
  - *Худший случай (обратно упорядоченный вход):* флаг ни разу не срабатывает досрочно.
    $$ C(n) = \sum_{i=0}^{n-2} (n - 1 - i) = \frac{n(n - 1)}{2} = \Theta(n^2) $$
- **Число обменов:**
  - Каждый обмен в Bubble Sort уменьшает число инверсий в массиве **ровно на 1**.
  - Следовательно, число обменов в точности равно числу инверсий во входных данных: $M(n) = I(a)$.
  - В худшем случае на обратном массиве без дубликатов $I = \frac{n(n-1)}{2}$. Значения счётчиков $C(n)$ и $M(n)$ совпадают с точностью до единицы!
- **Стабильность:** Строго стабилен. Условие обмена строгое (`res[j] > res[j + 1]`). Равные элементы никогда не меняются местами.

### 2.2. Сортировка вставками (`insertion_sort`)

```python
def insertion_sort(a: list, key=None) -> tuple[list, int, int]:
    res = list(a)
    n = len(res)
    comparisons, moves = 0, 0
    kfn = key if key is not None else (lambda x: x)
    for i in range(1, n):
        item = res[i]
        item_key = kfn(item)
        j = i - 1
        while j >= 0:
            comparisons += 1
            if kfn(res[j]) > item_key:
                res[j + 1] = res[j]
                moves += 1
                j -= 1
            else:
                break
        res[j + 1] = item
    return res, comparisons, moves
```

#### Инвариант внешнего цикла:
> Перед шагом $i$ префикс `res[0 .. i - 1]` состоит из тех же элементов, что и исходный срез `a[0 .. i - 1]`, но в строго отсортированном порядке.

#### Анализ сложности:
- **Адаптивность к инверсиям:**
  - Каждый сдвиг `res[j + 1] = res[j]` устраняет ровно 1 инверсию между вставляемым элементом и элементом `res[j]`.
  - Суммарное число сдвигов (перемещений) строго равно числу инверсий: $M(n) = I$.
  - Число сравнений удовлетворяет неравенству: $I \le C(n) \le I + n - 1$.
  - Временная сложность алгоритма равна $\Theta(n + I)$. При $I = O(n)$ (почти отсортированный массив) алгоритм работает за линейное время $\Theta(n)$.
- **Почему Insertion Sort быстрее Bubble Sort на практике?**
  1. *Меньше обращений к памяти:* При сдвиге перезаписывается только одна ячейка (`res[j + 1] = res[j]`), а вставляемый элемент удерживается в локальной переменной (регистре CPU). Пузырёк при каждом обмене перезаписывает две ячейки массива.
  2. *Меньше накладных расходов в Python:* Кортежный обмен `a[j], a[j+1] = a[j+1], a[j]` создаёт кортеж на внутреннем стеке интерпретатора, вставка выполняет прямое присваивание.
  3. *Кэш-локальность:* Внутренний цикл вставок обходит последовательный отрезок памяти назад, что эффективно кэшируется процессором (L1 Cache).

### 2.3. Сортировка выбором (`selection_sort`)

```python
def selection_sort(a: list, key=None) -> tuple[list, int, int]:
    res = list(a)
    n = len(res)
    comparisons, swaps = 0, 0
    kfn = key if key is not None else (lambda x: x)
    for i in range(n - 1):
        min_idx = i
        for j in range(i + 1, n):
            comparisons += 1
            if kfn(res[j]) < kfn(res[min_idx]):
                min_idx = j
        if min_idx != i:
            res[i], res[min_idx] = res[min_idx], res[i]
            swaps += 1
    return res, comparisons, swaps
```

#### Инвариант внешнего цикла:
> Перед $i$-й итерацией подмассив `res[0 .. i - 1]` содержит $i$ наименьших элементов массива в неубывающем порядке, причём каждый элемент этого подмассива не превосходит любого элемента суффикса `res[i .. n - 1]`.

#### Анализ сложности:
- **Инвариантность числа сравнений:**
  Внутренний цикл `for j in range(i + 1, n)` выполняется безусловно! В алгоритме нет никаких условий досрочного выхода. Следовательно, на **любом** массиве размера $n$ число сравнений равно:
  $$ C(n) = \frac{n(n - 1)}{2} $$
  Оно идентично для упорядоченного, случайного, обратно упорядоченного и состоящего из одинаковых элементов входов.
- **Минимальное число обменов:**
  Число обменов $M(n) \le n - 1$. На упорядоченном массиве обменов 0. На обратно упорядоченном — ровно $\lfloor n / 2 \rfloor$ парных перестановок.
- **Единственное достоинство Selection Sort:** Если запись во внешнюю память или диск (Flash/EEPROM) чрезвычайно дорога по сравнению с чтением, Selection Sort выигрывает у всех простых сортировок, так как делает строго не более $n - 1$ записей пар элементов.

### 2.4. Быстрая сортировка (`quick_sort`) с рандомизацией

```python
def quick_sort(a: list, rng: random.Random | None = None, key=None) -> list:
    if rng is None:
        rng = random.Random()
    res = list(a)
    n = len(res)
    if n <= 1:
        return res
    kfn = key if key is not None else (lambda x: x)

    stack = [(0, n)]
    while stack:
        lo, hi = stack.pop()
        if hi - lo <= 1:
            continue

        pivot_idx = rng.randrange(lo, hi)
        pivot_key = kfn(res[pivot_idx])

        # Трёхчастное разбиение Дейкстры (Dutch National Flag)
        lt, i, gt = lo, lo, hi - 1
        while i <= gt:
            cur_key = kfn(res[i])
            if cur_key < pivot_key:
                res[lt], res[i] = res[i], res[lt]
                lt += 1
                i += 1
            elif cur_key > pivot_key:
                res[i], res[gt] = res[gt], res[i]
                gt -= 1
            else:
                i += 1

        # Ограничение глубины стека: сначала больший, затем меньший
        left_len = lt - lo
        right_len = hi - (gt + 1)
        if left_len < right_len:
            if right_len > 1:
                stack.append((gt + 1, hi))
            if left_len > 1:
                stack.append((lo, lt))
        else:
            if left_len > 1:
                stack.append((lo, lt))
            if right_len > 1:
                stack.append((gt + 1, hi))
    return res
```

#### Анатомия трёхчастного разбиения Дейкстры:
Отрезок `[lo, hi)` в любой момент разбивается на 4 зоны:
1. `res[lo .. lt - 1]` — элементы строго `< pivot_key`.
2. `res[lt .. i - 1]` — элементы `== pivot_key`.
3. `res[i .. gt]` — ещё не просмотренные элементы.
4. `res[gt + 1 .. hi - 1]` — элементы строго `> pivot_key`.

Когда `i > gt`, нерассмотренная зона исчезает. Отрезок `[lt .. gt]` содержит элементы, равные опорному. **Они больше никогда не включаются в рекурсию!**
- Если во входном массиве все элементы равны (например, `[5, 5, 5, 5]`), за один проход `lt = lo`, `gt = lo - 1`, оба рекурсивных подмассива пусты! Время работы — строго $\Theta(n)$.

## Глава 3. Стабильность: теория и доказательства

### 3.1. Сводная таблица стабильности алгоритмов

| Алгоритм | Стабилен? | Причина стабильности / нестабильности |
| :--- | :--- | :--- |
| **Bubble Sort** | **ДА** | Обмениваются только строго нарушающие порядок смежные элементы (`>` вместо `>=`). |
| **Insertion Sort** | **ДА** | Сдвиг прекращается, как только встречен элемент `<= item`. Вставка происходит строго за равными. |
| **Selection Sort** | **НЕТ** | Минимальный элемент обменивается через голову промежуточных элементов, инвертируя порядок равных. |
| **QuickSort** | **НЕТ** | Элементы перебрасываются в противоположные концы диапазона относительно пивота через другие равные ключи. |

### 3.2. Наглядный контрпример для Selection Sort
Пусть дан массив пар `[(2, "a"), (2, "b"), (1, "c")]`.
1. Ищем минимум во всём массиве. Минимум — `(1, "c")` на индексе 2.
2. Меняем местами нулевой элемент `(2, "a")` и минимальный `(1, "c")`.
3. Получаем: `[(1, "c"), (2, "b"), (2, "a")]`.
4. Для ключа 2 порядок меток стал `["b", "a"]`, тогда как изначально было `["a", "b"]`.
**Стабильность нарушена.**

### 3.3. Наглядный контрпример для QuickSort
Пусть дан массив пар `[(2, "a"), (1, "b"), (2, "c"), (1, "d")]` и пивот выбран равным 2 (элемент `(2, "a")`).
1. При разбиении элемент `(1, "d")` перемещается в левый блок, а элемент `(2, "a")` перемещается вправо или меняется местами с `(1, "d")`.
2. На выходе получается: `[(1, "d"), (1, "b"), (2, "c"), (2, "a")]`.
3. И для ключа 1 порядок меток инвертирован (`["d", "b"]`), и для ключа 2 (`["c", "a"]`).
**Стабильность нарушена.**

## Глава 4. Быстрая сортировка (QuickSort): подводные камни и архитектура

### 4.1. Почему рандомизация спасает от $O(n^2)$?

> **Вопрос преподавателя:** *«Что мешает злоумышленнику подать такой вход, на котором рандомизированный QuickSort будет работать $O(n^2)$?»*

**Ответ:**
1. В детерминированном QuickSort (например, опорный — первый элемент) существует фиксированный вход (уже отсортированный массив), который *всегда* гарантирует худший случай. Злоумышленник может заранее сгенерировать такой вход.
2. В рандомизированном QuickSort выбор опорного элемента определяется не структурой входа, а внутренним генератором псевдослучайных чисел (ГПСЧ).
3. Чтобы алгоритм деградировал до $O(n^2)$, ГПСЧ должен на *каждом* из $n$ шагов разбиения случайно выбирать наименьший или наибольший элемент текущего подмассива.
4. Вероятность такого события для массива длины $n$:
   $$ P = \frac{2}{n} \cdot \frac{2}{n - 1} \cdot \frac{2}{n - 2} \cdots \frac{2}{3} \cdot 1 = \frac{2^{n - 1}}{n!} $$
5. Для $n = 100$: $\frac{2^{99}}{100!} \approx 10^{-128}$. Это число пренебрежимо мало (гораздо меньше вероятности разрушения компьютера космическим лучом).
6. Таким образом, худший случай зависит не от входа пользователя, а исключительно от случайных бит. Для *любого фиксированного входа* математическое ожидание времени работы составляет строго $O(n \log n)$.

### 4.2. Как устранить переполнение стека (RecursionError) в QuickSort?

> **Вопрос преподавателя:** *«В наивной рекурсивной реализации QuickSort в худшем случае глубина рекурсии равна $n$. В Python лимит рекурсии равен 1000, и при $n = 100\,000$ программа аварийно падает. Как вы решили эту проблему?»*

**Ответ:**
Проблема решается комбинацией двух приёмов:
1. **Явный стек подзадач вместо системного стека вызовов:**
   Вместо рекурсивных вызовов функция использует цикл `while stack:`, где в списке `stack` хранятся границы нерассмотренных отрезков `(lo, hi)`.
2. **Оптимизация хвостовой рекурсии (Tail-Call Optimization):**
   При разбиении отрезка на два подмассива длина одного из них $\le n / 2$.
   Мы **первым помещаем в стек больший подмассив**, а **меньший обрабатываем сразу** (или кладём последним, чтобы он извлёкся первым `pop()`).
   - Поскольку меньший подмассив имеет размер не более $n / 2$, максимальная глубина стека удовлетворяет рекуррентности:
     $$ D(n) \le D(n / 2) + 1 \implies D(n) \le \lceil \log_2 n \rceil $$
   - Для $n = 100\,000$ глубина стека в памяти гарантированно **не превышает 17 элементов**!

## Глава 5. Эмпирический анализ, log-log графики и Python-специфика

### 5.1. Анализ наклона в осях log-log

> **Вопрос преподавателя:** *«Почему на log-log графике степенная зависимость превращается в прямую и почему для QuickSort наклон равен $1.11 \dots 1.13$, а не ровно $1.00$?»*

#### Вывод формулы наклона:
Пусть время работы зависит от размера входа по степенному закону: $t(n) = C \cdot n^k$.
Прологарифмируем обе части по основанию 10:
$$ \log_{10} t = \log_{10} C + k \cdot \log_{10} n $$
В осях $Y = \log_{10} t$ и $X = \log_{10} n$ это уравнение прямой линии $Y = k \cdot X + B$, где угловой коэффициент (наклон) в точности равен показателю степени $k$:
$$ k = \frac{d(\log t)}{d(\log n)} $$

#### Почему у QuickSort наклон $\approx 1.12$, а не $1.00$?
Для алгоритма со сложностью $t(n) = C \cdot n \ln n$:
$$ \log t = \log C + \log n + \log(\ln n) $$
Производная (локальный наклон на log-log графике):
$$ k_{\text{eff}}(n) = \frac{d(\log t)}{d(\log n)} = 1 + \frac{1}{\ln n} $$
- Для $n = 1\,000$: $k_{\text{eff}} \approx 1 + \frac{1}{\ln 1000} \approx 1 + \frac{1}{6.91} \approx 1.14$.
- Для $n = 100\,000$: $k_{\text{eff}} \approx 1 + \frac{1}{\ln 100000} \approx 1 + \frac{1}{11.51} \approx 1.09$.
- Средний экспериментальный наклон на интервале $n \in [10^3, 10^5]$ равен $\approx 1.11 \dots 1.13$.
Это **строго соответствует теории $O(n \log n)$**! Наклон логарифмически медленно приближается к 1 при $n \to \infty$, но на любых реальных вычислительных размерах остаётся в диапазоне $1.10 \dots 1.15$.

## Глава 6. Банк самых каверзных вопросов преподавателя

### Вопрос 1. «Что произойдёт с QuickSort, если все элементы массива одинаковы?»
- **Ловушка:** В наивной схеме Ломуто (Lomuto partition) все элементы, равные пивоту, попадают в одну сторону. Алгоритм вырождается в худший случай $\Theta(n^2)$ даже на массиве `[1, 1, ..., 1]`.
- **Идеальный ответ:** «В нашей реализации применено трёхчастное разбиение Дейкстры (3-Way Partitioning). Элементы, равные пивоту, собираются в центральном блоке `[lt .. gt]` и полностью исключаются из дальнейшей обработки. Поэтому на массиве из одинаковых элементов наш алгоритм делает ровно 1 проход и завершается за строго линейное время $\Theta(n)$».

### Вопрос 2. «Почему в Insertion Sort на обратном массиве число сравнений и сдвигов одинаково, а на случайном — сравнений больше, чем сдвигов?»
- **Ответ:**
  1. На *обратном массиве* каждый вставляемый элемент меньше всех элементов уже отсортированного префикса. Поэтому на каждом шаге цикла `while` условие `res[j] > item` оказывается истинным, происходит сдвиг, и цикл доходит до самого левого края ($j = -1$). Ни одно сравнение не даёт `False`. Поэтому число сравнений строго равно числу сдвигов: $C(n) = M(n) = \frac{n(n-1)}{2}$.
  2. На *случайном массиве* поиск позиции вставки почти всегда останавливается на элементе, который меньше либо равен текущему (`res[j] <= item`). На этом элементе выполняется сравнение, условие оказывается ложным, и происходит `break`. Это последнее сравнение *не влечёт за собой сдвига*. Поскольку таких прерываний ровно $n - 1$ (по одному на каждый элемент с индекса 1 до $n-1$), число сравнений всегда превышает число сдвигов примерно на величину порядка $n$: $C(n) \approx M(n) + n$.

### Вопрос 3. «Можно ли ускорить Insertion Sort до $O(n \log n)$, если искать позицию для вставки бинарным поиском?»
- **Ловушка:** Студент думает, что бинарный поиск решает проблему.
- **Идеальный ответ:** «Бинарный поиск действительно сокращает число **сравнений** с $O(n^2)$ до $O(n \log n)$ (алгоритм Binary Insertion Sort). Однако число **физических перемещений (сдвигов)** в массиве остаётся равным числу инверсий $\Theta(n^2)$, поскольку элементы непрерывного массива всё равно нужно сдвигать в памяти вправо для освобождения ячейки. В модели RAM сдвиг одного элемента занимает $O(1)$, поэтому суммарное время работы останется $\Theta(n^2)$».

### Вопрос 4. «Почему при замерах в бенчмарке обязательно нужно передавать свежую копию `list(data)` на каждый повтор?»
- **Ответ:** «Все четыре функции сортировки работают in-place над переданным списком (или его копией). Если в цикле повторений передать один и тот же объект списка, то на первом же прогоне массив будет отсортирован. В результате 2-й, 3-й, 4-й и 5-й повторы будут замерять не время работы на случайном или обратном входе, а время работы на *уже отсортированном массиве*. Это грубейшим образом исказит результаты (вставки покажут $O(n)$ вместо $O(n^2)$). Создание свежей копии `arg = list(data)` перед каждым замером таймера гарантирует чистоту эксперимента».

### Вопрос 5. «Почему в Bubble Sort с досрочным выходом на упорядоченном массиве ровно $n - 1$ сравнений, а не $n$ или $n(n-1)/2$?»
- **Ответ:** «Внешний цикл делает ровно одну итерацию ($i = 0$). Внутренний цикл сравнивает пары `(0, 1), (1, 2), ..., (n - 2, n - 1)`. Количество таких соседних пар в массиве длины $n$ в точности равно $n - 1$. Ни в одной паре условие `res[j] > res[j + 1]` не выполняется, переменная `swapped` остаётся `False`, срабатывает проверка `if not swapped: break`, и алгоритм завершает работу, сделав ровно $n - 1$ сравнений».

### Вопрос 6. «Как метод двух указателей Хоара отличается от трёхчастного разбиения Дейкстры?»
- **Ответ:** «Разбиение Хоара использует два встречных указателя, которые останавливаются на элементах, нарушающих порядок относительно пивота, и обменивают их. Разбиение Хоара совершает в среднем в 3 раза меньше обменов, чем схема Ломуто. Однако при наличии большого числа дубликатов Хоар продолжает рекурсивно делить одинаковые элементы. Трёхчастное разбиение Дейкстры явно выделяет третью центральную группу `== pivot`, что даёт строго линейное время $\Theta(n)$ на мультимножествах с малым числом уникальных ключей».
